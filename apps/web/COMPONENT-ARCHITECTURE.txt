DATA FLOW WITH COMPONENTS
================================================================================

USER INTERACTION → COMPONENT → STATE → SUPABASE → REALTIME UPDATE

Example: Chat Flow
┌────────────────┐
│ User Message   │
│ → Input field  │
└────────┬───────┘
         │
┌────────▼────────────┐
│ Validate input      │
│ (client-side)       │
└────────┬────────────┘
         │
┌────────▼──────────────────┐
│ useChat hook               │
│ → Streaming response       │
│ → SSE parser              │
│ → Update UI (Reel cards)  │
└────────┬──────────────────┘
         │
┌────────▼──────────────┐
│ Fireworks API         │
│ (Edge Function proxy) │
└────────┬──────────────┘
         │
┌────────▼──────────────┐
│ LLM Response (stream) │
│ → Render in Reel      │
└───────────────────────┘

Example: Form Submission Flow
┌────────────────┐
│ Form Input     │
│ (Kibo Combobox,│
│  Dropzone,etc) │
└────────┬───────┘
         │
┌────────▼────────────┐
│ Validate Schema     │
│ (Zod)               │
└────────┬────────────┘
         │
┌────────▼──────────────┐
│ useFormSubmission     │
│ → Encrypt sensitive   │
│ → Upload files        │
│ → Save to Supabase    │

         │
┌────────▼──────────────┐
│ Notification         │

BUILD & PERFORMANCE OPTIMIZATION
================================================================================

Tree-shaking: Use individual imports
  ✅ import { Pill } from '@kibocorp/ui/pill'
  ❌ import { Pill } from '@kibocorp/ui'

Code Splitting: Lazy-load heavy components
  import dynamic from 'next/dynamic'
  const Editor = dynamic(() => import('@kibocorp/ui/editor'))

Bundle Analysis:
  npm run build && npm run analyze
  Expected impact per Kibo component: ~2-5KB gzipped

Performance Targets:
  - First Contentful Paint: < 2s
  - Largest Contentful Paint: < 3s
  - Cumulative Layout Shift: < 0.1
  - Lighthouse score: > 90

MIGRATION WORKFLOW
================================================================================

Step 1: Install Kibo package group
  → npm install @kibocorp/ui-{pill,banner,dialog-stack}

Step 2: Update component imports
  FROM: import { Button } from '@/components/ui/button'
  TO:   import { Pill } from '@kibocorp/ui/pill'

Step 3: Update component props
  Verify Kibo API differs from shadcn/ui
  Test on multiple viewports

Step 4: Test & validate
  ✅ npm run type-check
  ✅ npm run build
  ✅ npm run dev (manual testing)
  ✅ Keyboard nav & accessibility
  ✅ Mobile responsiveness

Step 5: Update docs
  Update this COMPONENT-MAP.md file
  Add component example to stories/docs

Step 6: Commit & PR
  One Kibo component per commit
  Include before/after screenshots

DECISION TREE: Keep Custom vs Use Kibo
================================================================================

Does the component need:
├─ External library integration (Mapbox, Canvas, etc)?
│  └─ YES → Keep CUSTOM
│
├─ Complex state management specific to FEED?
│  └─ YES → Keep CUSTOM
│
├─ Design system compliance & WCAG accessibility?
│  └─ YES → Use KIBO
│
├─ Simple UI display (nav, buttons, cards)?
│  └─ YES → Use KIBO
│
├─ Standard form input (text, select, date)?
│  └─ YES → Use KIBO (Combobox, Mini Calendar, etc)
│
└─ Performance critical hot path?
   └─ YES → Test both, measure bundle impact
